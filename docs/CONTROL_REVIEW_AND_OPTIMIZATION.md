# 末段滑翔制导控制审查与优化建议

## 1. 审查结论

目标是在末段同时满足：预测撞点接近目标、撞击姿态/航迹满足要求、迎角/舵面/动压/速率可实现。建议控制链保持：

```
视觉/航向误差外环 → 姿态内环 → 控制分配 → 舵机 ACL
                 ↘ 联合观测器和可行性约束
```

像素误差改成航向误差是正确方向，但不能因此声称已经完成动力学匹配。外环、内环和状态机必须在 v2 分层中分别实现，最终由 `FlightController` 编排；不要把 SDK 调用塞进控制类。

## 2. 外环风险

航向误差 `sigma = lambda_LOS - gamma` 的小侧滑近似为：

```
gamma_dot ≈ (A*alpha + a_g) / v
sigma_dot = lambda_dot_LOS - gamma_dot
```

因此滑模面 `s = sigma_dot + lambda_s*sigma` 对应的等效迎角至少含有 `v/A`、视线角速度和重力项。直接用 `kd*sat(s)` 会把“带边界层的 PD”误称为严格滑模，且在默认权限很小时长期饱和。实现前要检查：

- `lambda_s * |sigma| <= A*alpha_available/v` 是否可行；
- 视觉延迟和内环滞后是否会让到达律反相；
- `alpha`、`theta_cmd`、`theta_cmd_dot`、舵面位置和速率是否分别限幅；
- 离轴投影是否使用 `f*sec^2(angle)`，而非固定像素/弧度比例；
- 竖直通道是否显式包含重力，不把重力变化误当成目标运动。

## 3. 内环和末段

姿态内环离散求解只在模型、舵效、采样周期和限幅都满足时成立。必须加入：

1. 舵面饱和和速率限制的反馈；
2. `omega_cmd` 前馈和真实参考变化率；
3. 随速度/动压调度的 `Cm_alpha/Cm_delta`；
4. 观测器扰动的单位转换；
5. 舵效丢失或低动压下的保姿态退化。

固定 `t_go_terminal` 只能是初始实验旋钮。进入 `Terminal` 后清零外环能改善姿态，却会放弃剩余落点修正；更合理的是依据姿态捕获时间、可修正落点误差、状态不确定度、舵面余量和速度做渐变权重：

```
theta_cmd = w * theta_guidance + (1-w) * theta_terminal
```

如果终端姿态是目标平面法向，不得只用目标中心像素推断；需要目标几何、外部姿态或预先标定的参考。

## 4. 预测器接线要求

`JointObserver` 的目标接口在 `src/control/` 规划中，但还没有实现。接线时必须确认：

- 每个控制拍按实际 `dt` 推进，视觉按采样时间更新并外推到控制时刻；
- `residual_rate` 的坐标符号、机体角速度扣除只做一次；
- 观测器的按拍扰动和内环连续角加速度单位一致；
- 视觉延迟进入预测时间，不能用增大滑模增益掩盖；
- 出框、拒收、重置和未锚定状态禁止继续使用未经验证的外推；
- 协方差可用于调节边界层和权限，但不能替代硬安全上限。

## 5. 标定和试验顺序

### A：传感器与坐标

标定 IMU 零偏/噪声、相机内外参、机体/相机/目标坐标系和俯仰/偏航像素符号。把采样时间、曝光时间和处理完成时间分开记录。

### B：执行器与气动

做受限舵偏阶跃、迎角阶跃和侧向加速度测试，取得 `Cm_delta(v)`、`Cm_alpha(v)`、`A(v)`、零位、行程、速率和最低有效动压。

### C：内环

关闭外环，做姿态阶跃/斜坡，记录超调、捕获时间、稳态误差、饱和率、总变差、供电电压和实际舵位。确认 `b_hat` 单位以及舵效降低时的安全退化。

### D：观测器与外环

使用静止目标、匀速横移目标和已知旋转目标测像素噪声、视线角速度噪声、视觉延迟和帧间抖动；用 NIS、拒收和救援次数整定 Q/R。先闭合航向误差，再加入撞点/终端姿态约束。

### E：鲁棒性

覆盖不同初始偏差、距离、速度、丢帧、延迟、模型参数 ±30%~50%、舵面限幅、低动压、重力和横滚耦合。参数辨识数据、整定数据和最终验收数据必须分开。

## 6. 验收指标和数据记录

每次试验至少保存同一单调时钟下的：

- IMU 原始值、标定值、温度、饱和和 gap；
- 视觉原始浮点测量、曝光/取帧/完成时间、ROI、质量、跟踪状态；
- 观测器状态、协方差、innovation、NIS、拒收/救援/钳位；
- 外环误差、滑模面、限幅前后指令、可用权限；
- 内环误差、扰动估计、三轴力矩、分配前后舵偏和速率限幅；
- PWM、实际舵位（没有反馈时至少保留台架回读）；
- 模式切换、丢拍、队列满、硬件错误和恢复动作；
- 外部测得的撞点、撞击时刻、姿态、初始状态和环境条件。

高速数据用定长二进制环形队列异步落盘，不能在控制线程逐行格式化或 `fsync`。每条记录带 schema 版本、尺寸、序号、单调时间戳和有效位。日志只记录一次可恢复边界错误，正常“未检测到目标”进入计数器，不刷主日志。

## 7. 优化优先级

1. 先恢复可比较基线：CMake、工具链探针、接口契约和板端最小探针；
2. 再消除运行期分配、复制和所有权歧义；
3. 再做模型/雅可比合并、固定矩阵稀疏化和 cache 布局优化；
4. 最后才调增益或追求 RVV 微优化。

任何“优化”都必须同时给出正确性证据、最坏耗时、内存高水位和板端复现实验。没有这些数据，不把文件后缀变化或主机 benchmark 叫作完成。
