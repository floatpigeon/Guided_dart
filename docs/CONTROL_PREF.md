# 观测器与控制运行时预算

## 1. 推荐结构

视觉像素和 IMU 运动量进入同一个联合观测器，避免“先由 EKF 预测、再把同一预测结果作为伪测量融回去”的环路：

```
IMU（角速度/比力） ─┐
                    ├─ JointObserver ─→ 目标像素/视线角速度、姿态、速度和不确定度
视觉像素（带时间戳） ┘
```

每个通道可使用 `[theta, omega, u, v, b, mu, mu_dot, theta_anchor]` 这类固定状态，但状态定义、单位和过程模型必须在接口头文件中写明。深度若无法由传感器观测，不要伪装成可观状态；自身平移和目标运动应通过残差速度/过程噪声表达，并明确其适用时间范围。

联合滤波器的纪律：

- 一次像素观测只经过一次新息更新，互协方差负责在自身运动和目标残差之间分配信息；
- 外部拖曳/风预测器只能提供不含本滤波器输出的“本拍状态增量”，并校验时间区间；
- 上游检测质量门限与滤波器一致性门限分别保留，不能互相顶替；
- 未锚定、长时间丢视觉或投影被夹取时，交付值必须带无效/陈旧标志，不能继续当作真实预测。

## 2. 处理位置和实时预算

最终应用应按数据流决定核和线程，而不是按文档中的历史 CPU 编号硬编码：

- 视觉 RVV、VICAP 和帧池在拥有带宽的核/线程上运行；
- 观测器和控制环使用固定周期、无阻塞、无文件 I/O 的任务；
- ACL 负责把 SDK 线程模型和 cache/DMA 语义转换成上层可测试接口；
- 具体核绑定、频率和周期必须由板端探针与日志确认，当前没有可引用的 v2 实测基线。

运行态预算至少记录：每拍执行时间 p50/p95/max、最老输入年龄、丢拍数、堆分配次数、队列高水位和 cache/DMA 同步耗时。不要用 x86 主机纳秒数外推 K230 的实时性。

## 3. 计算与内存约束

固定尺寸状态和协方差可以利用稀疏雅可比、对称矩阵和复用倒数，但优化顺序必须是“先测量、再改写”：

1. 模型推进和雅可比在一次评估中完成，避免两份公式漂移；
2. 协方差只计算必要三角并在边界恢复对称；
3. 不在控制热路径临时创建大数组；工作区启动期分配并记录字节数；
4. `tan/sec^2` 等昂贵函数只放在确有需要的观测/交付路径，不能无意进入固定高频环；
5. 对每次稀疏化增加标量参考和有限时长稳定性检查，防越界、NaN 和正定性破坏。

优化目标不是“C 比 C++ 快”或某个固定百分比，而是：无运行期分配、无未界定循环、可证明的最坏执行时间和可诊断的退化路径。

## 4. 对外接口清单（实现时必须接线）

| 接口能力 | 调用方 | 不调用的后果 |
|---|---|---|
| `reset/seed` | 目标丢失、重捕获、参考系重置 | 残差会抱着旧目标外推 |
| `anchored/valid` | 控制器读取前 | 未锚定值进入外环 |
| `set_process_noise/gate` | 启动期配置 | 运行时使用未标定占位值 |
| `pixel_nis/rejects/rescues` | 诊断任务 | 无法判断 Q/R 或门限是否失配 |
| `projection_clamps` | 诊断任务 | 把出框钳值误当真实预测 |
| `residual_rate` | 视觉外环 | 只能用像素位置，无法闭合速度方向 |
| `disturbance_estimate` | 姿态内环 | 稳态扰动被迫由切换项承担 |

帧间隔不必假设为控制周期的整数倍；视觉帧应携带采样时间，观测器负责外推到控制时刻。像素 gate 只挡与运动模型不一致的观测，检测层仍需挡坏点、贴边和质量不足的候选。

## 5. 日志和验证

观测器日志应包含：状态有效位、输入年龄、协方差关键项、innovation、innovation variance、NIS、拒收/救援/投影钳位计数和当前模型版本。高频故障采用限频汇总；叶子层不重复打印。

主机只验证纯模型、矩阵、门限和错误注入；交叉构建验证 ABI/链接；板端验证实际周期、cache、丢帧、真实视觉延迟和控制闭环。任何性能表必须写明工具链、时钟、输入规模和测量日期，未测量的栏目写 `TBD`。

## 6. 尚待决定的问题

- 是否引入陀螺零偏状态，及其与锚点/残差的可观性；
- 何时把 `float` 替代 `double`，需先看协方差条件数和工具链代码生成；
- 独立预测器是否需要按时间戳而非按拍提交增量；
- 视觉前馈是否加入控制通路。没有验证横向重力项、延迟和权限前，前馈权重必须为零。
